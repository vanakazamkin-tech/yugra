# Территориальный crosswalk Yugra18 ↔ Росстат / ОКТМО

**Статус:** шаблон, не подтверждённый справочник.  
**Дата:** 07.11.2026.

Файл `data/rosstat/municipality-oktmo-crosswalk.template.csv` содержит 22 муниципалитета из `data/municipalities-detailed.json`. Поля официального наименования, ОКТМО, типа и срока действия оставлены пустыми намеренно: коды и исторические соответствия нельзя надёжно выводить из названия или внутреннего ID проекта. Добавлены поля для URL официального документа, SHA-256 исходного файла и даты проверки.

## Официальные основания

- [Территориальное устройство Росстата по Тюменской области, ХМАО—Югре и ЯНАО](https://72.rosstat.gov.ru/ofs_teru_hmao) — файл «Муниципальные образования за 2018–2026 годы», опубликован 05.02.2026.
- [Открытые данные Росстата: ОКТМО](https://www.rosstat.gov.ru/opendata/7708234640-oktmo) — набор с паспортом, структурой и данными классификатора.
- [Инструкция БД ПМО](https://rosstat.gov.ru/free_doc/new_site/bd_munst/instruction.htm) — Росстат указывает, что данные БД ПМО загружаются под актуальным на момент загрузки наименованием муниципального образования.

## Правила заполнения

1. Сверить каждый проектный муниципалитет с XLSX Росстата за 2018–2026 годы и действующим ОКТМО.
2. Заполнить точное официальное наименование, восьмизначный код ОКТМО муниципального уровня, тип МО и интервалы действия кода. Не подставлять одиннадцатизначные коды населённых пунктов вместо кода муниципального образования.
3. Если муниципалитет переименован, преобразован или изменил границы, добавить отдельные исторические строки/версии соответствия; не перезаписывать старый код без периода действия.
4. Один актуальный проектный ID может соответствовать нескольким историческим ОКТМО только через явно документированное правило агрегации. Не склеивать данные автоматически.
5. Если однозначное соответствие не подтверждено, оставить `pending_official_match` и пояснение.
6. Сохранять исходный XLSX, дату получения и SHA-256 рядом с итоговым crosswalk, чтобы его можно было воспроизвести.

## Контроль качества

Скрипт `scripts/validate-rosstat-crosswalk.mjs` читает эталонные ID и названия из `data/municipalities-detailed.json`, проверяет полный набор из 22 строк, отсутствие дублей и неизвестных ID, точное совпадение проектных названий, порядок/число CSV-колонок и восьмизначный формат ОКТМО. Для строки со статусом `matched` обязательны официальное имя, тип, дата начала действия, имя файла, URL, SHA-256 и дата проверки. Пустые коды допускаются только со статусом `pending_official_match`.

**На текущем шаге:** 22/22 проектных записи внесены в шаблон; 0/22 кодов ОКТМО подтверждены в этом файле. Это сознательная защита от выдуманных территориальных кодов.
