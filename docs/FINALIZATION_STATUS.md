## 5.1. Дополнительная проверка migration drift и staging import

На 18.11.2026 выявлен конкретный drift между GitHub и production Supabase:

- В production `supabase_migrations.schema_migrations` последняя версия — `20261107055919`.
- В GitHub уже существует `20261107122134_allow_cross_source_staging_import.sql`, но эта версия не зарегистрирована в production.
- Живая `import_accepted_municipality_indicators(text)` соответствует ранней реализации `20261105234455`: поиск дубликата не учитывает `source_id` и `geographic_name`, поэтому независимая запись другого источника может быть ошибочно признана уже существующей.
- Живое review-представление использует `coalesce(raw_period, 'annual')`, а фактическая RPC импортирует пустую строку через `nullif(raw_period, '')`. Это даёт разные ключи для пустого периода.
- На `municipality_indicators` нет триггера, который автоматически создаёт provenance-link. Исторические 1 445 private links были сформированы миграционным backfill; старый staging importer не вставляет ссылку для новых строк.
- На момент проверки staging пуст (`0` строк), а в private provenance table находится `1 445` links. Поэтому обнаруженные дефекты не повредили существующие наблюдения.

В рабочую ветку добавлена forward migration `20261118033000_harden_staging_import_integrity.sql` (пока НЕ применена к production). Она:
1. Добавляет в staging нормализованный период, точный URL снимка, дату публикации и фактическое время получения.
2. Запрещает статус `accepted` без ручного рецензента, валидного normalized period, очищенного списка validation errors, municipality mapping и фактической даты получения.
3. Согласует review-view и RPC на полном ключе наблюдения: муниципалитет, код, год, нормализованный период, единица, геоуровень, географическое имя и источник.
4. Сохраняет независимые значения разных источников, но ловит same-source duplicates.
5. При успешном импорте записывает `source_url`, `source_published_at`, `retrieved_at` и создаёт primary-link в `private.municipality_indicator_source_links`.
6. Доступ к RPC по-прежнему остаётся только у `service_role`; публичные RLS-политики не добавляются.

Добавлен `scripts/test-staging-import-integrity.mjs` и подключён в `scripts/test-all.mjs`. Этот контрактный тест в текущей сессии локально не исполнялся: локальный Node checkout недоступен из-за сетевой ошибки клонирования.
