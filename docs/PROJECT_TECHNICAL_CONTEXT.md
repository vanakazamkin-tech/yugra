## 1. Назначение продукта

Yugra18 — веб-платформа для анализа, сравнения и сценарного прогнозирования социально-экономической устойчивости 22 муниципальных образований ХМАО — Югры. Предполагаемые пользователи — специалисты регионального Департамента экономического развития и муниципальных администраций.

Основные разделы приложения: карта и паспорта муниципалитетов, сравнение территорий, каталог и матрица статистических данных, мониторинг рисков, конструктор отчётов и концептуальные сценарные расчёты на горизонте 1–3 года.

Визуальное оформление использует мотивы орнаментов ханты и манси.

## 2. Технологический стек и структура

- React 18, Vite 5, JavaScript/JSX, ESM.
- `src/main.jsx` — точка входа приложения.
- `src/InvestmentDetails.jsx` — основной компонент интерфейса и навигация по разделам.
- `src/components/UgraMap.jsx`, `src/ugraMapGeo.js` — карта и геометрия.
- `src/components/Forecasting.jsx` — сценарный модуль прогнозирования.
- `src/components/UnifiedRiskForecast.jsx` и связанный CSS — модуль рисков.
- `src/components/AppErrorBoundary.jsx` — граница обработки ошибок приложения.
- `src/lib/officialData.js`, `src/lib/supabase.js` — загрузка подтверждённых данных и подключение Supabase.
- `src/lib/riskModel.js`, `riskSeries.js`, `riskDirection.js`, `indicatorClassification.js` — расчёты рисков, временные серии и классификация направлений.
- `src/lib/forecastModel.js`, `forecastCoverage.js` — сценарные расчёты и диагностика покрытия.
- `src/lib/resilienceIndex.js`, `forecastIndexAdapter.js` — кандидатная методика индекса и адаптер.
- `data/municipalities-detailed.json` — локальный резервный и демонстрационный слой.
- `supabase/migrations/` — SQL-история проекта.
- `supabase/audits/` — read-only SQL-запросы для анализа состояния базы.
- `scripts/test-all.mjs` — дополнительные regression- и QA-проверки.

В приложении существуют два разных аналитических слоя: демонстрационный/проектный рейтинг основного интерфейса и отдельный слой подтверждённых наблюдений Supabase.

## 4. Состояние истории миграций на 18.11.2026

В зафиксированном аудите Git-репозитория было 110 SQL-файлов миграций, а в production-таблице `supabase_migrations.schema_migrations` — 96 зарегистрированных версий. Последняя зарегистрированная версия на дату проверки: `20261107055919`.

В Git были обнаружены повторяющиеся префиксы версий:

- `20261030194500`
- `20261030200000`
- `20261030201500`
- `20261030203000`

Состав файлов миграций в репозитории не совпадал один-к-одному с production migration history. В частности, файлы `20261107114255_harden_external_rating_review_default.sql`, `20261107122134_allow_cross_source_staging_import.sql` и `20261118033000_harden_staging_import_integrity.sql` присутствовали в Git, но на дату аудита не были зарегистрированы как применённые в production.

Миграция `20261118033000` проходила тестирование на live PostgreSQL в транзакции с ROLLBACK. Этот тест не являлся подтверждением применения миграции в production.

Supabase Advisor на дату проверки показывал 5 таблиц с включённым RLS без политик и 13 неиспользуемых индексов. Эти результаты сами по себе не определяли, являются ли соответствующие настройки ошибочными: часть закрытых staging/provenance/project-таблиц могла быть намеренно недоступна публичным ролям.

## 5. Состояние данных и методологических компонентов

Подтверждённые наблюдения хранят сведения об источнике, URL (при наличии), коде и определении показателя, единице измерения, годе, периоде, географическом уровне и статусе проверки.

В проекте различаются муниципальный и поселенческий уровни географии. В доступных данных также встречаются неполные временные ряды, пропуски, межисточниковые расхождения, разные единицы и периоды.

Номинальные денежные значения в зафиксированном наборе не были скорректированы на инфляцию. Накопительные срезы Q1/H1/Q3/год не являются независимыми периодами и не образуют сумму при сложении.

РИА Рейтинг используется как внешний бенчмарк. Внешние рейтинговые значения могут относиться к региональному или городскому уровню; их наличие не означает наличия сопоставимых муниципальных значений для всех 22 территорий.

Шестинаправленный индекс устойчивости на дату документации являлся кандидатной методикой, а не утверждённым официальным индексом. Сценарный модуль рассчитывал условные варианты на основе задаваемых параметров, а не результат обученной на подтверждённых временных рядах модели. Пороговые значения риск-модуля также представляли собой настройки концепта, а не утверждённые нормативы. Полнота покрытия и сопоставимость рядов оставались важными ограничениями интерпретации.

## 6. Команды проекта

В `package.json` на дату документации были доступны следующие команды:

- `npm ci` — установка зависимостей по lockfile.
- `npm test` — основной набор Node QA/regression-проверок.
- `npm run build` — production-сборка.
- `npm run check:map-coverage` — проверка покрытия карты.
- `npm run check:risk-pilot-csv` — проверка пилотного CSV.
- `npm run validate:rosstat-crosswalk` — проверка справочника муниципалитетов Росстата.

Отдельного lint-скрипта в зафиксированной версии `package.json` не было. GitHub Actions также выполнял отдельный PostgreSQL migration integration workflow на тестовой схеме. Успех этого workflow не подтверждал изменение production Supabase.
