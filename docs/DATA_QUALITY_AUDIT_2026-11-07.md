### Уточнение по числу полностью покрытых кодов

Проверка разделяет наличие строки и подтверждённое покрытие. Девять кодов встречаются на всех 22 территориях при учёте любых статусов, но только **8 кодов имеют verified-наблюдения по всем 22 муниципалитетам**. Код `sme_employment_share` является причиной расхождения: Нягань имеет 0 verified и 4 needs_review строки; Урай и Югорск — по 1 verified и 4 needs_review. Для сопоставимого муниципального анализа подтверждённый охват этого кода равен 21, а не 22.

По verified-строкам распределение 243 кодов: 8 с полным охватом, 75 с охватом 2–21 муниципалитет, 156 только с одним муниципалитетом, 4 без verified-наблюдений муниципального уровня. Неподтверждённые строки не должны расширять официальный охват.

## 5. Диагностика качества после миграции

Представление `public.municipality_indicator_quality_issues` показывает:

| Тип проблемы | Записей/групп |
|---|---:|
| Межисточниковые конфликты значений | 6 |
| Нестандартные метки периода | 4 |
| Наблюдения `needs_review` | 12 |
| Различия единиц измерения между источниками в одном ключе | 0 |

Шесть конфликтов — это разные значения из разных источников для одного сопоставимого ключа; это не технические дубли. Двенадцать наблюдений `needs_review` относятся к Нягани, Ураю и Югорску. Их не следует использовать как подтверждённые. Четыре нестандартные метки периода требуют сверки первичного документа.

Read-only preflight перед установкой уникального индекса не выявил дублей внутри одного источника по полному ключу:
`municipality_id + indicator_code + reference_year + reference_period + unit + geographic_level + geographic_name + source_id`.
При этом межисточниковые различия сохранены.
