# Аудит формы Росстата № 1-МО и муниципального сборника Тюменьстата (06.11.2026)

Рабочая записка для ветки `claude-stage1-2-preview`. Это аудит источников и правил сопоставления, а не импорт наблюдений. Production и Supabase не изменялись.

## 1. Вывод по источникам

### 1.1. Сборник Тюменьстата «Социально-экономический мониторинг муниципальных образований ХМАО — Югры (2023–2025)»

- Публикация выпуска подтверждена официальной новостью Тюменьстата от 21.10.2026: https://72.rosstat.gov.ru/anons_tmn?print=1
- По названию и заявленному охвату это приоритетный источник для проверки новых муниципальных рядов за 2023–2025 годы.
- На дату аудита поисковая выдача подтверждает выпуск, но не предоставляет сам файл сборника и перечень его таблиц. Страница анонсов при прямом открытии вернула ошибку 502. Поэтому ни одна таблица/строка/значение из сборника не считается извлечённой.
- Следующий шаг — получить именно файл сборника, зафиксировать имя, URL, дату скачивания и контрольную сумму; затем составить инвентарь листов/таблиц с названием, страницей, показателем, единицей, периодом, географией, ОКТМО и примечаниями методики.
- Не восстанавливать муниципальные значения из региональных агрегатов и не считать факт публикации доказательством доступности данных в Supabase.

### 1.2. Форма № 1-МО

Форму № 1-МО следует трактовать как источник сведений об объектах инфраструктуры муниципального образования, а не как универсальную форму для всей социально-экономической статистики. В частности, в материалах Росстата по форме выделены разделы территории, объектов бытового обслуживания, спортивных сооружений, коммунальной сферы, здравоохранения и почтовой/телефонной связи. Для образования и ряда других социально-экономических направлений используются другие формы и источники (например, 85-К, 1-ДОД, БД ПМО), что уже отражено в основной карте источников.

Официальные материалы для проверки:
- Росстат, муниципальная статистика: https://www.rosstat.gov.ru/munstat
- Информационная памятка Тюменьстата к приложению к форме № 1-МО (годовая), по состоянию на 31.12.2025: https://72.rosstat.gov.ru/storage/mediabank/Приложение%20к%20ф.%201-МО_2025.pdf
- Материал Росстата об изменениях и заполнении формы № 1-МО: https://28.rosstat.gov.ru/storage/mediabank/1(141).pdf

Важно различать:
- собственно форму № 1-МО «Сведения об объектах инфраструктуры муниципального образования»;
- приложение к форме № 1-МО с показателями для оценки эффективности деятельности органов местного самоуправления;
- перечень показателей БД ПМО, в котором рядом могут указываться коды показателей и формы наблюдения.

Это связанные, но не взаимозаменяемые наборы. Код показателя БД ПМО не является автоматически кодом `indicator_code` приложения и не доказывает наличие наблюдения в базе проекта.

### 1.3. ОКТМО и географическая сопоставимость

- Официальный открытый набор ОКТМО Росстата: https://rosstat.gov.ru/opendata/7708234640-oktmo
- На странице указано обновление набора 01.10.2026 и учёт изменений 951/2026.
- ОКТМО — ключ идентификации территории, но одного совпадения названия муниципалитета недостаточно. Для каждой записи требуется проверять код, тип/уровень муниципального образования и период действия.
- Отдельный набор перекодировки аннулированных ОКТМО населённых пунктов не является полным crosswalk муниципальных образований. Его нельзя применять в одиночку для присвоения кодов муниципалитетам или агрегации поселений.

При разборе формы/сборника фиксировать уровень наблюдения как одно из значений: субъект РФ, городской округ, муниципальный район, муниципальный округ, городское/сельское поселение, населённый пункт. Нельзя автоматически агрегировать или разукрупнять эти уровни.

## 2. Контрольные правила для формы № 1-МО

1. Проверять 11-значный код ОКТМО и допустимый тип кода для соответствующего уровня. Не исправлять код эвристически только по названию.
2. Для муниципальных районов и входящих поселений проверять правила сводных строк формы и не складывать итоговую строку с её подстроками.
3. Различать муниципальную территорию и населённый пункт внутри неё. Строки «в том числе по населённым пунктам» не являются дополнительными муниципалитетами.
4. Проверять годовой отчётный период и дату состояния показателя. Запас/количество объектов на конец года — моментный показатель; протяжённость/объём за период может иметь другой смысл.
5. Сохранять исходные единицы. Не смешивать километры и метры, количество объектов и количество мест, объём ТКО в тыс. м³ и массу ТКО в тыс. тонн.
6. Для долей и удельных весов сохранять определение числителя и знаменателя. Производный показатель рассчитывать только при совпадении охвата и географии исходных величин.
7. Разделять «всего» и подгруппы «в том числе»; не суммировать их повторно.
8. Фиксировать редакцию формы/указаний, дату публикации и статус значения (факт, предварительный факт, оценка, план).

## 4. План извлечения сборника 2023–2025

После получения файла:

1. Сохранить исходный файл без изменений и зафиксировать SHA-256.
2. Составить каталог всех таблиц/листов и страниц; отдельно отметить общие региональные итоги.
3. Для каждой таблицы извлечь метаданные: точное название, показатель, единица, год/период, тип территории, ОКТМО (если указан), примечание, источник формы.
4. Отфильтровать только строки по муниципальным образованиям Югры. Не распределять региональные итоги по муниципалитетам.
5. Сопоставить с существующими рядами по семантике, единице, геоуровню, периоду и методике; одинаковое название не считать достаточным совпадением.
6. Отдельно пометить точные дубликаты, методологические разрывы и потенциально новые ряды.
7. Сформировать staging CSV и отчёт проверки: число территорий, периодов, значений, пропусков, дубликатов и неразрешённых кодов ОКТМО.
8. Только после аудита решать, какие ряды годятся для индекса, какие — для контекстных карточек, а какие нужно исключить.
