## 2. Официальная муниципальная статистика — главный приоритет

Росстат продолжает предоставлять БД показателей муниципальных образований (БД ПМО) как отдельный официальный сервис. В каталоге баз данных Росстата также перечислены ЕМИСС и паспорта муниципальных образований. Региональные страницы Росстата описывают БД ПМО как официальную статистику по муниципальным образованиям; интерфейс БД позволяет выбирать показатель, тип муниципального образования, муниципалитет, год и период.

Ссылки:
- [Каталог баз данных Росстата](https://rosstat.gov.ru/databases)
- [БД ПМО Росстата](https://www.rosstat.gov.ru/storage/mediabank/munst.htm)
- [Интерфейс запроса БД ПМО](https://rosstat.gov.ru/dbscripts/munst/munst30/DBInet.cgi?pl=8006001)
- [Базы данных Тюменьстата](https://72.rosstat.gov.ru/folder/32922) — региональная точка входа для БД ПМО и ЕМИСС.

В каталоге Yugra18 источник `rosstat_municipal` зарегистрирован, но остаётся `identified`. Сам факт доступности интерфейса не подтверждает, что конкретный показатель есть по всем 22 муниципалитетам Югры. До импорта для каждого показателя необходимо сохранить:
1. точное название и код показателя из перечня соответствующего года;
2. тип муниципального образования и ОКТМО;
3. фактически выбранные муниципалитеты;
4. год и период;
5. единицу измерения и методологическое примечание;
6. дату выгрузки, исходный файл и его контрольную сумму;
7. пропуски и изменения состава территорий.

**Рекомендация:** формировать из БД ПМО не одну большую «панель», а поочерёдные проверенные выгрузки по приоритетным блокам (демография, занятость/труд, местные финансы, жильё и инфраструктура). Сначала подтвердить покрытие 22 МО для каждого показателя, только затем включать его в межмуниципальное сравнение.

### 3.3 Как использовать данные Мегиона

Разделить данные на два класса:

**Локальный инфраструктурный слой:** объекты, координаты, адреса, остановки, площадки, учреждения, разрешения и инвестиционные площадки. Их можно использовать в паспорте Мегиона и на карте, если проверены актуальность и полнота. Такие записи не должны увеличивать муниципальный интегральный индекс как будто это статистический ряд.

**Муниципальные статистические наблюдения:** тарифы, цены, бюджетные и социально-экономические величины. Их можно сравнивать с другими МО только при наличии сопоставимых определений, единиц, периода и методики по всем территориям. Набор только по Мегиону не должен автоматически попадать в общий рейтинг 22 МО.

## 4. Другие важные выводы по каталогу

1. **Ссылки на портал/раздел вместо прямого паспорта набора.** Для некоторых записей Мегиона в `data_sources.url` хранится общий URL `/datasets/`. По возможности в карточке источника следует хранить точный URL конкретного набора; общий портал оставить как URL владельца/каталога в описании или метаданных.
2. **Дата паспорта и дата данных — разные поля.** Проверять отдельно `last_updated_at` паспорта, дату последней версии файла, период наблюдений и дату фактической выгрузки. Ни одна из этих дат не должна подменять другую.
3. **Частота обновления — обещание владельца, не факт свежести.** Если заявлена еженедельная/ежеквартальная публикация, а последняя версия старше нескольких циклов, ставить флаг проверки и не обновлять `last_checked_at` без реального подтверждения.
4. **Рейтинги РИА Рейтинг** сохранять отдельным аналитическим слоем. Региональный результат ХМАО не переносить на муниципалитеты; городские результаты использовать только для тех городов, которые прямо присутствуют в публикации.
5. **Локальные муниципальные отчёты** остаются полезными для паспортов отдельных территорий и верификации, но не являются заменой равномерной панели по 22 МО.

## 6. Запреты и критерии приёмки

- Не менять production Supabase в рамках этого документа.
- Не менять `import_status` без подтверждённого импорта.
- Не заполнять даты проверки, даты публикации, периодичность и ограничения доступа догадками.
- Не загружать устаревшие локальные реестры как актуальные значения.
- Не создавать муниципальные значения из региональных рейтингов.
- Не сравнивать показатели с разными единицами, периодами, географией или методологией.
- Не превращать инфраструктурные реестры в статистические индикаторы без обоснованной модели.

Следующий этап считается выполненным, когда по каждому источнику есть прямая ссылка, владелец, тип данных, география, период, дата последней версии, частота (или честная отметка «по событию»), дата фактической проверки и решение о пригодности: `comparable_panel`, `local_profile_only`, `context_only` или `not_usable_yet`.
