# Протокол подготовки бюджетного приложения Думы Югры к импорту

## Источник

- Источник каталога: `duma_hmao_municipal_budget_2023_2024_appendix1`
- Документ: приложение 1 к анализу исполнения бюджетов муниципальных образований ХМАО — Югры за 2023–2024 годы.
- PDF: https://www.dumahmao.ru/povest/0745_4/03/50.pdf
- Объём: 8 страниц.
- Территории: 13 городских округов и 9 муниципальных районов.
- Денежная единица в документе: тыс. рублей.

## Что подготовлено

`scripts/prepare-duma-budget-import.mjs` принимает CSV с ручной транскрипцией и формирует JSON для проверки. Скрипт:
- сопоставляет только известные названия 22 муниципальных образований с текущими ID;
- принимает только 2023 и 2024 годы и страницы 1–8;
- исключает строку «ВСЕГО» из муниципальных наблюдений, сохраняя её в отдельном контрольном массиве;
- сохраняет исходное значение в `value_raw`, а число помещает в `value` только при однозначном разборе;
- сохраняет «св.100», пропуски и прочие нечисловые ячейки как флаги ручной проверки, не подменяя их числами;
- требует явного `indicator_code`, единицы, типа величины (`amount` или `growth_rate`), страницы и названия таблицы;
- отмечает дубли и покрытие муниципалитетов по годам;
- ставит всем строкам `needs_review`.

Скрипт не скачивает PDF, не выполняет OCR и не записывает данные в Supabase. Это намеренно: автоматическое распознавание многостраничных таблиц с повторяющимися заголовками и значениями «св.100» без визуальной сверки создаёт риск неверного сопоставления колонок.

## Формат CSV

Разделитель — точка с запятой. Заголовок:

```csv
municipality;indicator_code;indicator_name;measure_type;year;value_raw;unit;page;table_title
```

Пример строки ниже — только тестовая фикстура формата, не реальное наблюдение из PDF:

```csv
г.Сургут;budget_total_revenue;Доходы бюджета — всего;amount;2024;1234,5;тыс. руб.;1;Итого доходов
```

`indicator_code` нельзя заполнять только по похожему названию. Например, код `budget_total_revenue` уже используется в базе, но до повторного использования необходимо подтвердить совпадение определения и состава доходов в источнике и в словаре. Темпы роста — отдельный тип показателя и не должны записываться в денежный код.

## Запуск

```bash
node scripts/prepare-duma-budget-import.mjs extracted-manual.csv --out=duma-budget-review.json
```

Выполнить проверку:

```bash
npm run test:data-quality
```


## Кандидаты на сопоставление со словарём (только read-only проверка production)

В production уже существуют следующие коды с единицей `тыс. руб.` и географией `municipality`:

| Кандидат из PDF | Существующий код | Наблюдения в базе на момент проверки | Решение |
|---|---|---:|---|
| Итого доходов | `budget_total_revenue` | 44, 22 МО, 2024–2025 | Кандидат; подтвердить состав доходов и исключения |
| Итого расходов | `budget_total_expenditure` | 44, 22 МО, 2024–2025 | Кандидат; сверить методику исполнения расходов |
| Налоговые и неналоговые доходы | `budget_tax_non_tax_revenue` | 44, 22 МО, 2024–2025 | Кандидат; проверить, что определение совпадает |
| Доходы без безвозмездных поступлений | `budget_revenue_excluding_grants` | 44, 22 МО, 2024–2025 | Кандидат; не считать автоматически тождественным налоговым и неналоговым доходам |

Это список для ручной проверки, а не готовый mapping. Количество и покрытие получены SELECT-запросом к production. В staging-файле код должен быть указан явно после сверки определения, единицы, периода и уровня географии. Коды темпов роста в этой таблице не предлагаются.

## Блокирующие условия до загрузки

1. Сверить каждую транскрибированную ячейку с PDF, включая страницу, заголовок колонки и год.
2. Подтвердить соответствие всех 22 названий актуальным муниципальным ID и историческому уровню территории.
3. Для каждого показателя подтвердить точное определение и существующий код; не создавать маппинг по одному только сходству названий.
4. Убедиться, что единицы совпадают с кодом. Не умножать тыс. руб. на 1 000 без документированного решения.
5. Темпы роста хранить отдельно от денежных сумм. «св.100» не преобразовывать в 100.
6. Пустые значения не заменять нулём; отрицательные значения не отбрасывать.
7. Сравнить контрольные суммы с итоговой строкой «ВСЕГО» там, где арифметическая сверка применима.
8. Перед фактическим импортом отдельно подготовить и проверить staging/review batch. Этот скрипт сам ничего не загружает.

## Текущее состояние

Источник найден в production-каталоге, статус `identified`. Подготовка staging-инструмента не меняет статус источника, наблюдения, миграции или production Supabase. Фактическая транскрипция и импорт пока не выполнены.
