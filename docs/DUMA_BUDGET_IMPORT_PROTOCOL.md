# Протокол подготовки бюджетного приложения Думы Югры к импорту

## Источник

- Источник каталога: `duma_hmao_municipal_budget_2023_2024_appendix1`
- Документ: приложение 1 к анализу исполнения бюджетов муниципальных образований ХМАО — Югры за 2023–2024 годы.
- PDF: https://www.dumahmao.ru/povest/0745_4/03/50.pdf
- Объём: 8 страниц.
- Территории: 13 городских округов и 9 муниципальных районов.
- Денежная единица в документе: тыс. рублей.

## Что подготовлено

`scripts/prepare-duma-budget-import.mjs` принимает CSV с ручной транскрипцией и формирует JSON для проверки. Скрипт:
- сопоставляет только известные названия 22 муниципальных образований с текущими ID;
- принимает только 2023 и 2024 годы и страницы 1–8;
- исключает строку «ВСЕГО» из муниципальных наблюдений, сохраняя её в отдельном контрольном массиве;
- сохраняет исходное значение в `value_raw`, а число помещает в `value` только при однозначном разборе;
- сохраняет «св.100», пропуски и прочие нечисловые ячейки как флаги ручной проверки, не подменяя их числами;
- требует явного `indicator_code`, единицы, типа величины (`amount` или `growth_rate`), страницы и названия таблицы;
- отмечает дубли и покрытие муниципалитетов по годам;
- ставит всем строкам `needs_review`.

Скрипт не скачивает PDF, не выполняет OCR и не записывает данные в Supabase. Это намеренно: автоматическое распознавание многостраничных таблиц с повторяющимися заголовками и значениями «св.100» без визуальной сверки создаёт риск неверного сопоставления колонок.

## Формат CSV

Разделитель — точка с запятой. Заголовок:

```csv
municipality;indicator_code;indicator_name;measure_type;year;value_raw;unit;page;table_title
```

Пример строки ниже — только тестовая фикстура формата, не реальное наблюдение из PDF:

```csv
г.Сургут;budget_total_revenue;Доходы бюджета — всего;amount;2024;1234,5;тыс. руб.;1;Итого доходов
```

`indicator_code` нельзя заполнять только по похожему названию. Например, код `budget_total_revenue` уже используется в базе, но до повторного использования необходимо подтвердить совпадение определения и состава доходов в источнике и в словаре. Темпы роста — отдельный тип показателя и не должны записываться в денежный код.

## Запуск

```bash
node scripts/prepare-duma-budget-import.mjs extracted-manual.csv --out=duma-budget-review.json
```

Выполнить проверку:

```bash
npm run test:data-quality
```

## Блокирующие условия до загрузки

1. Сверить каждую транскрибированную ячейку с PDF, включая страницу, заголовок колонки и год.
2. Подтвердить соответствие всех 22 названий актуальным муниципальным ID и историческому уровню территории.
3. Для каждого показателя подтвердить точное определение и существующий код; не создавать маппинг по одному только сходству названий.
4. Убедиться, что единицы совпадают с кодом. Не умножать тыс. руб. на 1 000 без документированного решения.
5. Темпы роста хранить отдельно от денежных сумм. «св.100» не преобразовывать в 100.
6. Пустые значения не заменять нулём; отрицательные значения не отбрасывать.
7. Сравнить контрольные суммы с итоговой строкой «ВСЕГО» там, где арифметическая сверка применима.
8. Перед фактическим импортом отдельно подготовить и проверить staging/review batch. Этот скрипт сам ничего не загружает.

## Текущее состояние

Источник найден в production-каталоге, статус `identified`. Подготовка staging-инструмента не меняет статус источника, наблюдения, миграции или production Supabase. Фактическая транскрипция и импорт пока не выполнены.

### Проверка периодов и существующих наблюдений

Read-only запрос к production показал, что по каждому из трёх кодов уже есть по 22 наблюдения за `2024-Q3` и `2025-Q3` (по 66 строк на каждый квартальный срез). Это данные за 9 месяцев, а не годовое исполнение. В CSV для PDF указан годовой `reference_period = 2024` или `2023`, поэтому годовой показатель за 2024 год не следует смешивать с `2024-Q3`; в логическом ключе это разные периоды. Тем не менее перед любым импортом нужно проверить, что downstream-агрегации и UI не группируют их только по `reference_year` и не скрывают разницу между годом и 9 месяцами.

Источник PDF пока имеет статус `identified` и не связан ни с одним наблюдением. CSV остаётся review fixture; production не менялся.

Добавлен тест `scripts/test-duma-budget-page1-transcription.mjs`, который проверяет 132 строки, 22 МО в каждом году, отсутствие неразобранных значений/дублей и совпадение шести сумм с контрольной строкой PDF.

Для двух других денежных колонок первой страницы — «Налоговые доходы» и «Налог на доходы физических лиц» — подходящие общие коды муниципального уровня с единицей `тыс. руб.` в текущем словаре не найдены. Найденные `local_budget_tax_revenue` и локальные налоговые записи имеют единицу `руб.` и единичное покрытие; использовать их для этой таблицы без отдельного решения нельзя. Поэтому эти колонки и все темпы роста пока не включены в review CSV, а не переименованы в близкие коды.

### Сохранение колонок без подтверждённого кода

Чтобы не терять значения, отдельно сохранены ещё 88 ячеек первой страницы: «Налоговые доходы» и «Налог на доходы физических лиц» — 22 МО × 2 года × 2 показателя. Файл: `supabase/imports/review/duma_budget_page1_unmapped_tax_columns.csv`.

Текущий парсер выдаёт флаг `indicator_mapping_required` для каждой строки; эти данные не могут быть ошибочно импортированы под похожий, но несовместимый код. Для налоговых доходов есть лишь единичная локальная запись в рублях, а отдельного общего кода НДФЛ в тыс. руб. не обнаружено. Добавлен тест `scripts/test-duma-budget-unmapped-tax-columns.mjs`, проверяющий сохранение всех 88 значений и обязательную ручную классификацию.

## Уточнение по текстовому слою PDF (повторная проверка страниц 2–3)

Повторно изучен извлечённый текстовый слой исходного восьмистраничного PDF. Он подтверждает наличие на следующих страницах нескольких самостоятельных подстатей, а не одной простой таблицы с единой парой годовых значений.

### Страница 2 PDF (индекс страницы 1)

В заголовках явно присутствуют:
- «Неналоговые доходы»;
- «Безвозмездные поступления от других бюджетов бюджетной системы Российской Федерации»;
- «Безвозмездные поступления от государственных (муниципальных) организаций»;
- «Безвозмездные поступления от негосударственных организаций»;
- «Прочие безвозмездные поступления»;
- отдельные колонки темпа роста к соответствующему периоду 2023 года.

В строках 22 муниципалитетов есть отрицательные значения, пустые позиции и текстовые значения «св.100» в темпах роста. Извлечённый текст не сохраняет надёжно горизонтальные координаты всех пустых ячеек. Поэтому по одному порядку чисел нельзя безошибочно назначить каждое значение конкретному заголовку. Кандидат budget_intergovernmental_transfers относится только к суммарной статье поступлений от других бюджетов, а не к сумме всех видов безвозмездных поступлений или к подстатьям от организаций. Для остальных подстатей коды автоматически не назначаются.

### Страница 3 PDF (индекс страницы 2)

В заголовках явно присутствуют:
- «Оплата труда, начисления на выплаты по оплате труда (с учетом бюджетных и автономных учреждений)»;
- «Капитальные вложения в объекты государственной (муниципальной) собственности (с учетом бюджетных и автономных учреждений)»;
- «Итого расходов»;
- возвраты остатков субсидий, субвенций и иных целевых межбюджетных трансфертов прошлых лет;
- соответствующие темпы роста.

Код budget_payroll_fund является только кандидатом: его определение должно совпасть с составом оплаты труда и начислений в PDF. Код budget_total_expenditure — кандидат для итоговой статьи расходов, но не для капитальных вложений или возвратов остатков. Капитальные вложения в государственную/муниципальную собственность не приравниваются к статистическому показателю инвестиций в основной капитал: охват и экономический смысл могут различаться.

### Решение по транскрипции

Новые CSV для страниц 2–3 не создавались. До получения надёжного визуального изображения страниц нельзя подтвердить позицию пустых ячеек и соответствие каждой числовой группы годам/подстатьям. Не следует:
- сдвигать значения через пустые ячейки;
- превращать «св.100» в 100;
- заменять пустоты нулями;
- объединять разные виды безвозмездных поступлений;
- смешивать капитальные вложения бюджета с инвестициями в основной капитал;
- присваивать темпам роста денежные коды.

Это ограничение относится к качеству исходного извлечения, а не к отсутствию данных в PDF. Страница 1 остаётся отдельной проверенной транскрипцией; её 132 строки не менялись.

### Следствия для импорта

1. Для трёх показателей первой страницы уже подготовленная годовая транскрипция 2023–2024 остаётся отдельным review-набором. Существующие `2024-Q3` и `2025-Q3` не являются дублями годовых `2024` и `2025`.
2. Для межбюджетных трансфертов и фонда оплаты труда существующий код и охват 22 МО подтверждены, но наблюдения есть только за `2025-Q3`. Это не подтверждает возможность восстановить годовые значения 2023–2024 из базы.
