# Подготовка муниципальных рядов миграции Росстата

## Источники

- Основной источник: [База данных показателей муниципальных образований Росстата](https://rosstat.gov.ru/storage/mediabank/MUNST.htm).
- [Перечень показателей БД ПМО на 2025 год](https://60.rosstat.gov.ru/storage/mediabank/SVOD250207_1.htm) подтверждает три годовых ряда для всех типов муниципальных образований:
  - `8112021` — число прибывших;
  - `8112022` — число выбывших;
  - `8112023` — миграционный прирост.
- [Обработанный набор «Муниципальная статистика России с 2005 года»](https://tochno.st/datasets/bdmo) — вспомогательный вариант выгрузки данных, преобразованных из БД ПМО Росстата. Он не заменяет сверку с исходной базой Росстата.

## Безопасный порядок импорта

1. Скачай CSV-выгрузку из БД ПМО Росстата либо из вспомогательного набора. Для вспомогательного набора выбери раздел «31. Население» и распакуй архив.
2. Выбери файл, содержащий год, регион, муниципальное образование, значение и номер показателя в БД ПМО. Для автоматического отбора в поле номера должны присутствовать коды `8112021`, `8112022`, `8112023`.
3. Запусти staging-скрипт. По умолчанию он читает CSV с разделителем `;`:
   ```sh
   node scripts/prepare-rosstat-migration-import.mjs ./path/to/export.csv --out=./migration-review.json
   ```
4. Если заголовки отличаются от стандартных, передай точные названия столбцов:
   ```sh
   node scripts/prepare-rosstat-migration-import.mjs ./path/to/export.csv \
     --year="Год" \
     --municipality="Муниципальное образование" \
     --value="Значение" \
     --indicator="Номер показателя в БД ПМО" \
     --region="Регион" \
     --unit="Единица измерения" \
     --out=./migration-review.json
   ```
5. Проверь `staged_rows`, `unmatched_municipality_names` и `duplicate_keys`. Скрипт намеренно не сопоставляет автоматически поселения с муниципалитетом верхнего уровня, если название не совпадает с известным названием.
6. Сверь каждую запись с исходной БД ПМО Росстата: код показателя, год, тип муниципального образования, значение и территориальные границы. Особенно внимательно проверь муниципальные преобразования и разрывы длинных рядов.
7. Только после сверки сформируй отдельную проверяемую миграцию/импорт. Не отмечай значения как `verified` только на основании успешного разбора CSV.

## Защитные ограничения

- Скрипт только создаёт локальный JSON для проверки и **не записывает данные в Supabase**.
- Все подготовленные записи получают статус `REVIEW_REQUIRED`; это метка staging-файла, а не допустимый статус в базе.
- Регион обязателен и фильтруется на ХМАО — Югру, чтобы не смешать значения из других субъектов РФ.
- Сопоставление по названию — предварительное. Неоднозначные названия, нераспознанные территории и дубликаты требуют ручной проверки.
- Ноль подготовленных строк означает, что формат/коды столбцов не совпали с ожиданиями; это не доказательство отсутствия миграционной статистики.
- В проекте пока нет подтверждённых числовых наблюдений по миграции. До завершения проверки покрытие миграции остаётся 0 из 22 и не трактуется как нулевая миграция.
