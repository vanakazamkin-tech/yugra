## Расхождения октябрьской истории

Сопоставление версий БД с именами и содержимым SQL-файлов выявило 12 версий из журнала Supabase, отсутствующих в репозитории под теми же версиями.

- Для 9 миграций найдено содержимое с точным совпадением SQL, но под другими временными префиксами в именах файлов.
- Миграция Покачей `20261030144702_import_pokachi_ser_report_2022_2024` отличается от одноимённого по смыслу файла в GitHub. Перед объединением нужно сравнить импортируемые значения, а не только форматирование.
- Две миграции Когалыма из журнала (`20261030145152`, `20261030145200`) не имеют точных одноимённых файлов; в GitHub лежат более поздние файлы с изменённым/расширенным содержимым.

Также 23 файла GitHub не имеют точного соответствия по версии в журнале БД. Часть из них — альтернативные версии тех же SQL-операций, остальные могут быть не применёнными или объединёнными миграциями.

## Правило до завершения сверки

**Не запускать полный `supabase db push` и не применять все файлы каталога автоматически.** Это может повторно импортировать данные, изменить уже проверенные значения или создать конфликтующие записи.

Безопасный порядок дальнейшей работы:

1. Сопоставить каждую пару «версия БД — файл GitHub» по SQL и по затрагиваемым строкам.
2. Отдельно проверить миграции Покачей и Когалыма на предмет различий в значениях.
3. Определить, какие 23 файла являются ожидаемыми pending-миграциями, а какие — устаревшими альтернативами.
4. Сформировать воспроизводимую историю миграций без повторного применения уже выполненных импортов.
5. Перед любым изменением данных проверить число строк, логические ключи и статусы до/после.

До этой сверки текущая рабочая база остаётся источником фактического состояния; GitHub содержит восстановленные миграции и документированное предупреждение о неполной синхронизации истории.
