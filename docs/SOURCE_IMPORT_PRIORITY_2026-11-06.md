# Очередь проверки и импорта источников Yugra18 — 06.11.2026

Документ фиксирует приоритеты работы с уже зарегистрированными источниками каталога. Он не подтверждает импорт и не меняет статусы в Supabase. Все кандидаты остаются `identified`, пока конкретные файлы не выгружены, не проверены и не загружены через staging.

## Приоритет 2 — дополнительные социальные и инфраструктурные показатели

- Муниципальная перепись 2020: использовать как срез переписной даты 01.10.2021, а не как ежегодный временной ряд. Таблицы с муниципальной географией отделять от региональных таблиц по КМНС.
- Муниципальные наборы Мегиона и Нижневартовска: потенциально полезны для инфраструктурных паспортов и локального анализа, но не создают сопоставимое покрытие всех 22 МО. Не включать их автоматически в общий рейтинг.
- Росстат — малое и среднее предпринимательство: сначала установить фактический уровень географии. Региональные показатели нельзя записывать как муниципальные.
- Данные по тарифам, остановкам, объектам культуры, спорта, торговли и строительства: использовать как справочно-инфраструктурный слой, отдельно от показателей муниципальной социально-экономической панели.

## Правила для бюджетного PDF Думы Югры

1. Одна строка на муниципалитет и год; годовые значения 2023 и 2024 сохраняются отдельно.
2. Денежные суммы в PDF выражены в тыс. рублей. Перед записью в базу определить, какая единица предусмотрена соответствующим `indicator_code`; конвертацию выполнять только явно и документировать множитель.
3. Темп роста к 2023 году — самостоятельная относительная величина, не денежная сумма и не абсолютный прирост.
4. Пустая ячейка не равна нулю. Отрицательные значения не запрещены автоматически.
5. Текстовые отметки «св.100» нельзя безоговорочно преобразовывать в 100: сохранить исходное представление и определить смысл по заголовку таблицы.
6. Строку «ВСЕГО» исключить из муниципальных наблюдений, но можно хранить отдельно как контрольную сумму.
7. Для каждого наблюдения хранить точную ссылку на PDF, страницу и название таблицы в доступных provenance-полях.
8. Не загружать данные до проверки соответствия муниципальных названий и единиц. После импорта сравнить суммы по территории и итоговую строку, где арифметически уместно.

## Что не делать

- Не менять `identified` на `imported` только потому, что ссылка открывается.
- Не загружать региональные показатели в муниципальные строки.
- Не превращать пропуски в нули.
- Не сливать две версии одного показателя от разных источников без проверки определений.
- Не переносить данные из производного набора в категорию первичных официальных наблюдений.
- Не запускать массовый импорт по общему landing page каталога, если конкретный файл/набор не идентифицирован.
